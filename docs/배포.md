# 배포 (Firebase + Cloud Run)

백엔드는 Cloud Run, 프론트는 Firebase Hosting, 로그인은 Firebase Authentication(Google)을 쓴다.
`main`에 머지하면 GitHub Actions(`.github/workflows/deploy.yml`)가 Docker 이미지를 빌드해 Cloud Run에 배포한다.

```
학생 브라우저
   │
Firebase Hosting ── 프론트 (프론트 담당자가 배포)
   │  /api/** → Cloud Run (같은 주소라 CORS 불필요)
Cloud Run "backend" (서울, 최대 2대, 요청 없으면 0대)
   │  실행 계정 backend-runtime: Secret Manager의 DATABASE_URL만 읽을 수 있음
PostgreSQL (Neon 무료)

GitHub Actions ── 배포 계정 github-deployer
   ① Docker 이미지 빌드 → ② Artifact Registry "backend"에 업로드 → ③ Cloud Run 배포
```

| 항목 | 값 |
|---|---|
| GCP / Firebase 프로젝트 | `gdg-1234` (결제 연결됨) |
| 리전 | `asia-northeast3` (서울) |
| Cloud Run 서비스 | `backend` |
| Artifact Registry 저장소 | `backend` (최근 이미지 5개만 유지, 정책: `deploy/artifact-cleanup-policy.json`) |
| 실행 계정 | `backend-runtime@gdg-1234.iam.gserviceaccount.com` |
| 배포 계정 | `github-deployer@gdg-1234.iam.gserviceaccount.com` |

---

## 1. 처음 한 번만 하는 설정 (프로젝트 소유자 권한 필요)

`gcloud auth login`으로 로그인한 상태에서 실행한다. 아래는 PowerShell 기준이다.

### 1-1. API 켜기
```powershell
gcloud services enable run.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com iam.googleapis.com --project gdg-1234
```

### 1-2. 이미지 저장소와 정리 정책
```powershell
gcloud artifacts repositories create backend --repository-format=docker --location=asia-northeast3 --project gdg-1234
gcloud artifacts repositories set-cleanup-policies backend --location=asia-northeast3 --policy=deploy/artifact-cleanup-policy.json --no-dry-run --project gdg-1234
```

### 1-3. 서비스 계정 두 개
```powershell
gcloud iam service-accounts create backend-runtime --display-name="Cloud Run backend 실행" --project gdg-1234
gcloud iam service-accounts create github-deployer --display-name="GitHub Actions 배포" --project gdg-1234
```

### 1-4. DB 주소 비밀값 (Secret Manager)
DB 주소에는 비밀번호가 들어 있으므로 **콘솔에서 직접 입력**한다. 채팅, 문서, 코드에 붙여 넣지 않는다.

1. https://console.cloud.google.com/security/secret-manager?project=gdg-1234 → 보안 비밀 만들기
2. 이름 `DATABASE_URL`, 값에 Neon 연결 주소(`postgresql://...?sslmode=require`)를 붙여 넣고 만들기

그다음 실행 계정만 읽을 수 있게 연결한다.
```powershell
gcloud secrets add-iam-policy-binding DATABASE_URL --member="serviceAccount:backend-runtime@gdg-1234.iam.gserviceaccount.com" --role="roles/secretmanager.secretAccessor" --project gdg-1234
```

### 1-5. 배포 계정 권한 (배포에 필요한 것만)
```powershell
# Cloud Run 배포, 공개 접근 설정
gcloud projects add-iam-policy-binding gdg-1234 --member="serviceAccount:github-deployer@gdg-1234.iam.gserviceaccount.com" --role="roles/run.admin" --condition=None
# 이미지 업로드 (backend 저장소에만)
gcloud artifacts repositories add-iam-policy-binding backend --location=asia-northeast3 --member="serviceAccount:github-deployer@gdg-1234.iam.gserviceaccount.com" --role="roles/artifactregistry.writer" --project gdg-1234
# 실행 계정으로 서버 띄우기 (backend-runtime에만)
gcloud iam service-accounts add-iam-policy-binding backend-runtime@gdg-1234.iam.gserviceaccount.com --member="serviceAccount:github-deployer@gdg-1234.iam.gserviceaccount.com" --role="roles/iam.serviceAccountUser" --project gdg-1234
```

### 1-6. 배포 계정 키를 GitHub에 등록
키 파일은 GitHub Secret에 넣고 **바로 지운다.** backend 레포 관리자 권한이 필요하다.
```powershell
gcloud iam service-accounts keys create key.json --iam-account=github-deployer@gdg-1234.iam.gserviceaccount.com --project gdg-1234
Get-Content key.json -Raw | gh secret set GCP_SA_KEY -R GDG-1234/GDGoC_project_backend_repository
Remove-Item key.json
gh variable set GCP_PROJECT_ID --body gdg-1234 -R GDG-1234/GDGoC_project_backend_repository
```

### 1-7. 첫 배포
GitHub → Actions → Deploy → **Run workflow** (또는 `main`에 머지).
서버가 켜질 때 DB 테이블이 자동으로 만들어진다 (`alembic upgrade head`).

### 1-8. 관리자 이메일
Cloud Run 콘솔 → `backend` → 새 버전 수정 및 배포 → 변수 및 보안 비밀

| 이름 | 값 |
|---|---|
| `ADMIN_EMAILS` | 관리자 이메일, 쉼표로 구분 |
| `ALLOWED_EMAIL_DOMAINS` | (선택) 허용 도메인, 쉼표로 구분. 비우면 모든 Google 계정 허용 |

한 번 설정하면 이후 자동 배포에서도 유지된다.

### 1-9. 마무리
- 소유자 권한을 원래 역할로 낮춰 달라고 프로젝트 관리자에게 알린다.
- 이후 배포는 `main` 머지만 하면 된다. 1번 설정은 다시 하지 않는다.

## 2. 프론트 연결 (프론트 담당자 작업)

`firebase.json`에서 `/api/**` 요청을 Cloud Run으로 넘기고, 빌드할 때 `VITE_API_BASE_URL=/api/v1`로 둔다.

```json
{
  "hosting": {
    "public": "dist",
    "rewrites": [
      { "source": "/api/**", "run": { "serviceId": "backend", "region": "asia-northeast3" } },
      { "source": "**", "destination": "/index.html" }
    ]
  }
}
```

프론트는 Firebase SDK로 Google 로그인한 뒤, API를 부를 때마다 헤더에 ID 토큰을 붙인다.

```ts
const token = await auth.currentUser?.getIdToken();
fetch("/api/v1/users/me", { headers: { Authorization: `Bearer ${token}` } });
```

## 3. API 요약 (프론트 전달용)

| API | 설명 |
|---|---|
| `GET /api/v1/users/me` | 내 정보. **처음 호출하면 회원가입**된다. `isAdmin`으로 관리자 여부 확인 |
| `GET /api/v1/admin/users` | 전체 사용자 목록 (관리자 전용) |
| 로그아웃 | 백엔드 API 없음. 프론트에서 Firebase `signOut()` |

에러 코드: `UNAUTHORIZED`(401, 토큰 없음·잘못됨·만료), `FORBIDDEN`(403, 관리자 아님), `EMAIL_NOT_ALLOWED`(403, 허용되지 않은 도메인)

## 4. 로컬 개발

```bash
cp .env.example .env      # FIREBASE_PROJECT_ID=gdg-1234. DATABASE_URL을 비우면 SQLite(local.db)
uv run alembic upgrade head
uv run fastapi dev app/main.py
```

## 5. 비용
팀 내부 사용 규모에서는 무료 사용량 안이다.
- Cloud Run: 요청이 없으면 0대, 최대 2대로 제한
- Artifact Registry: 최근 이미지 5개만 유지
- Secret Manager: 비밀값 1개
- DB: Neon 무료 (GCP 비용 없음)

비용이 생길 수 있는 변경(최소 인스턴스 1 이상, 최대 인스턴스 증가, Cloud SQL 도입)은 팀에 먼저 공유한다.

## 6. 확인이 필요한 것
- Firebase Hosting을 거칠 때 스트리밍(SSE) 응답이 끊기지 않는지 (채팅 스트리밍 구현 때 확인)
- Cloud Run은 요청이 없으면 꺼져서 첫 요청이 몇 초 걸린다. 시연 전에 한 번 호출해 둔다.
